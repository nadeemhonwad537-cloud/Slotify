## Defects, fixes, and retests

An application behavior defect was reproduced from the context-switch guard: selecting a division audience without filling any other field was not treated as unsaved content, so the switch handler skipped its confirmation and cleared that selection. The guard now uses a tested helper that includes audience selections; focused tests passed 2/2. A separate test-harness defect was confirmed: Vitest and global setup read the disposable target/reset consent only from `.env`, preventing explicit process-only overrides. The shared resolver now accepts process overrides while preserving the disposable-name regex, loopback-host requirement, and exact `YES` reset consent; `.env` was not edited. Two regression tests cover process override resolution and fail-closed invalid overrides.

Faculty workflow source tracing identified another frontend defect: Preferences did not surface selected-term submission-detail query failures, while Availability lacked failure feedback and allowed editing before the term's submission detail had loaded. Both now use a shared fail-closed query-state helper, show retryable loading errors, and prevent edits/saves until the current-term data loads successfully. Four database-independent regression tests cover idle, loading, ready and error states, including error with cached data. The changes do not establish API/database persistence or authenticated UI behavior.

Faculty timetable source tracing then identified a cross-account cache-isolation defect: its TanStack Query key omitted the authenticated faculty profile ID, while the shared QueryClient retains fresh results across logout/login for 30 seconds. Two faculty members selecting the same academic context could see the previous profile's cached sessions during that interval, although backend reads are profile-scoped. The key now includes the active profile ID, with a database-independent test asserting keys differ between faculty profiles. Browser account-switch verification remains outstanding.

The known null-to-undefined faculty-profile query issue has a null-safe query result and database-independent regression tests from prior work; it was not re-exercised through the browser/API in this audit.

Two concrete incompleteness findings are retained rather than reported as complete:

1. Timetable validation blocks UNKNOWN availability and does not accept the existing override marker. Do not use override status as evidence of valid availability; policy and implementation need to be reconciled before publication depending on overrides.
2. Student pages cannot be scoped to an authenticated student's actual division because no reliable student-to-section/elective mapping exists.

Neither finding was changed because the first needs a confirmed policy decision and the second needs an approved enrollment model. No destructive actions or data fabrication were used.
